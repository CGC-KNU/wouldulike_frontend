# 새 프로젝트 프롬프트 — 우주라이크 웹 스탬프

아래 전체를 새 프로젝트의 첫 프롬프트로 넘긴다.

---

## 만들 것
앱을 설치하지 않은 손님이 **매장 계산대 QR을 찍으면 모바일 웹에서 스탬프를 적립**하고, 적립 직후 **앱 설치로 유도**되는 웹앱. 앱 설치 허들 때문에 다운로드가 정체돼서, 웹에서 먼저 스탬프를 쌓게 한 뒤 설치를 유도하는 것이 목적이다.

- 스택: **Vite + React + TypeScript**, 모바일 우선(폭 360~430px 기준), 라우팅은 react-router.
- 디자인: **토스·도도포인트처럼 익숙하고 가벼운 UI** (큰 타이틀, 하단 고정 CTA 버튼, 카드, 넉넉한 여백, 부드러운 전환). 우주라이크 메인 컬러는 인디고 `#312E81`.
- 언어: 한국어.

## 핵심 설계: 같은 계정으로 이어받기
웹도 앱과 **같은 카카오/애플 계정 로그인**을 쓴다. 웹에서 로그인해 적립하면 그 스탬프가 처음부터 그 계정의 스탬프라서, 앱 설치 후 **같은 계정으로 로그인하면 자동으로 반영**된다. 별도 병합 로직은 만들지 않는다. 로그인 토큰만 저장한다.

## 사용자 흐름
1. **진입**: `https://<웹도메인>/s/:restaurantId?src=sticker` (QR 주소). 매장 정보 조회 → 매장명·스탬프 현황 안내 화면.
2. **로그인**: 토큰이 없으면 카카오(필수)·애플(선택) 간편로그인. 로그인 후 원래 화면으로 복귀. 토큰이 있으면 건너뜀(재방문 즉시 인식).
3. **적립**: 매장 PIN(4자리, 숫자패드 UI) 입력 + 개수(1~4, 기본 1) → 적립. PIN 오류/잠금/일일 상한 초과 메시지를 그대로 안내.
4. **적립 완료**: 현재 스탬프 판(칸 UI)과 변화를 보여준다. 보상 쿠폰이 나오면 축하 연출.
5. **앱 설치 유도 바텀시트**: 적립 직후 노출.
   - 진입 API의 `install_bonus_coupon === true`인 매장만 **"앱 설치까지 하면 쿠폰도 드려요!"** 문구와 `install_bonus_items` 쿠폰 목록을 보여준다.
   - `false`인 매장은 쿠폰 문구 없이 일반 안내만("앱에서 스탬프와 혜택을 한곳에서 확인해요").
   - 버튼: "앱 설치하고 이어서 보기" (iOS App Store / Android Play 스토어, UA로 분기), "나중에".
   - 안내: "앱에서 **같은 카카오(애플) 계정으로 로그인**하면 지금 쌓은 스탬프가 그대로 이어져요."
6. **재방문**: 같은 QR을 다시 찍으면 저장된 토큰으로 로그인 단계 없이 바로 적립 화면.

## 앱 설치 여부 분기 (이 프로젝트 밖, 참고)
앱 설치 여부 판단과 앱 이동은 QR이 먼저 거치는 브릿지(`wouldulike_deeplink`, GitHub Pages)가 한다. **앱이 있으면 앱으로, 없으면 이 웹의 `/s/:restaurantId`로 보낸다.** 이 프로젝트는 웹 쪽 도착 화면만 책임진다. 단 웹 화면 안에서도 `wouldulike://restaurant/{id}` 로 "앱에서 열기" 링크를 하나 둔다.

## 백엔드 API
Base URL: `https://deliberate-lenette-coggiri-5ee7b85e.koyeb.app` (환경변수 `VITE_API_BASE`). 모든 JSON.

| 용도 | 요청 | 비고 |
|---|---|---|
| 매장 정보 (로그인 전) | `GET /api/web/stamp/restaurants/{id}/` | 404=제휴 아님/없음 |
| 카카오 로그인 | `POST /api/auth/kakao` `{ "code": "...", "redirect_uri": "<콜백주소>" }` | 인가코드 방식 |
| 애플 로그인 | `POST /api/auth/apple/login/` `{ "identity_token": "...", "full_name"?, "email"? }` | |
| 토큰 갱신 | `POST /api/auth/token/refresh/` `{ "refresh": "..." }` | |
| 스탬프 적립 | `POST /api/coupons/stamps/add/` `{ "restaurant_id", "pin", "count" }` + `Authorization: Bearer <access>` | `Idempotency-Key` 헤더에 UUID를 붙여 재전송 안전하게 |
| 내 스탬프 | `GET /api/coupons/stamps/my/?restaurant_id={id}` + Bearer | |
| 정책값 | `GET /api/config/policy/` | `stamp.daily_limit_per_restaurant`(=4), `stamp.max_per_scan`(=4), `pin.length`(=4) |

### 응답·에러 요점
- 로그인 응답: `{ token: { access, refresh, access_expires_at, refresh_expires_at }, user: { id, nickname, ... }, is_new }`.
- 진입 응답: `{ restaurant_id, name, address, image_url, stamp: { enabled, cycle_target, rewards[], notes }, install_bonus_coupon, install_bonus_items[{title, subtitle}] }`. `stamp.enabled === false`면 적립 불가 매장이라 안내 화면만 보여준다.
- 적립 성공: 200, 보상이 나오면 201 + `reward_coupon_code`, `reward_coupons`/`reward_details`.
- 적립 에러(`code`): `invalid_pin`(403, 남은 시도 정보 포함) · `pin_locked`(403) · `stamp_daily_limit_reached`(429, 하루 매장당 최대 4개) · `invalid_stamp_count`(400) · `stamp_disabled`(400). 서버가 내려주는 `detail` 한글 메시지를 그대로 보여준다.
- 401이면 refresh로 갱신 후 재시도, 실패하면 로그인 화면으로.
- 하루 상한이 4개이므로 "오늘 N/4 적립" 같은 안내를 두되, 현재 남은 개수를 API로 주지는 않으니 **정책값 기반 안내 + 429 처리**로 한다.

## 토큰 저장 (쿠키/로컬 저장)
- access/refresh 토큰을 브라우저에 저장해 재방문 시 자동 로그인한다. 구현은 `localStorage`(try/catch로 감싸고 실패 시 메모리 폴백)로 하고, 사파리 ITP 등으로 지워질 수 있으니 **지워져도 카카오 재로그인 한 번이면 같은 계정으로 복구**되는 구조임을 UX 문구에 반영한다.
- 마지막으로 본 `restaurantId`도 저장해, 로그인 리다이렉트 후 복귀에 쓴다 (`sessionStorage`의 `returnTo`).

## 카카오 로그인 구현
- 카카오 인가 페이지(`https://kauth.kakao.com/oauth/authorize?client_id=<REST_API_KEY>&redirect_uri=<콜백>&response_type=code&state=<returnTo>`)로 이동 → 콜백 라우트 `/auth/kakao`에서 `code`를 받아 `POST /api/auth/kakao`에 `code`와 **동일한 `redirect_uri`** 를 보낸다.
- 콜백 주소는 환경변수 `VITE_KAKAO_REDIRECT_URI`. 이 값이 백엔드 허용 목록(`KAKAO_WEB_REDIRECT_URIS`)과 카카오 콘솔 Redirect URI에 **정확히 같게** 등록돼 있어야 한다.
- 카카오 인앱 브라우저에서도 동작해야 한다.
- 애플 웹 로그인은 Services ID가 준비되면 추가(1차 범위에서는 버튼 자리만).

## 화면 목록
`/s/:id` 진입 · 로그인 · `/auth/kakao` 콜백 · PIN+개수 적립 · 적립 완료(스탬프 판) · 앱 설치 바텀시트 · 오류/비제휴 매장 안내 · PC 접속 시 "휴대폰으로 QR을 다시 찍어 주세요".

## 비기능
- 스탬프 판은 `stamp.cycle_target`(없으면 10) 칸, 보상 칸은 `rewards[].stamps` 위치에 표시.
- PIN 입력 실패 시 입력칸 흔들림 등 즉각적 피드백, 중복 제출 방지.
- 접근성: 버튼 터치 영역 44px 이상, 포커스 표시, 대비 확보.
- GA4 이벤트(있으면 쉽게 붙일 수 있게 훅만 분리): `web_stamp_view`, `web_login`, `web_stamp_add`, `web_install_click`(쿠폰 문구 노출 여부 포함), `src` 값 포함.
- Vercel 배포를 가정한 정적 SPA(`vercel.json`에 SPA rewrite).

## 배포 전 확정이 필요한 것 (사용자 확인)
- 웹 도메인 → 백엔드 `CORS_ALLOWED_ORIGIN_LIST`, `KAKAO_WEB_REDIRECT_URIS`와 카카오 콘솔에 등록.
- iOS/Android 스토어 URL, 브릿지의 "앱 없음" 분기를 이 웹 주소로 바꾸는 작업(별도 저장소).
- 운영 환경변수 `STAMP_DAILY_EARN_LIMIT`가 따로 5로 설정돼 있지 않은지.

## 먼저 할 일
1. 프로젝트 생성과 라우팅, API 클라이언트(토큰 갱신 인터셉터 포함), 환경변수 정리.
2. 진입 → 카카오 로그인 → PIN 적립 → 설치 바텀시트의 가로지르기(end-to-end)를 먼저 완성.
3. 이후 디자인 다듬기, 오류 상태, GA4.
